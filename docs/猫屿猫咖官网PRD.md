## 1. 项目概述

### 1.1 背景与目标

为单店猫咖「猫屿 CAT ISLE」建设官网，包含**前台企业展示官网**与**后台管理系统**两个子系统。设计参考日本连锁猫咖 **CAT CAFE MOCHA**（catmocha.jp/zh/concept）：用极简治愈的视觉承载情感化品牌叙事，卖"陪伴时光"而非服务。技术实现采用 **FastAPI（后端）+ React（前端）**，数据库 **SQLite**。

### 1.2 设计原则（对齐参考网站）

- **治愈系叙事**：文案诗意化、短句分段、猫咪实拍先行（"那一天的你和，猫"式的情绪表达）
- **日式极简美学**：暖咖米白色板、大量留白、圆角系统、单栏长滚动叙事
- **猫咪即主角**：每只猫有名字、性格、故事，档案独立成页

### 1.3 系统范围

| 子系统 | 包含 | 不包含 |
| --- | --- | --- |
| 前台展示系统 | 首页（长滚动）、猫咪列表/详情、餐单、预约、领养、隐私政策 | 会员体系、在线支付、多语言、小程序/App |
| 后台管理系统 | 管理员登录、仪表盘统计、猫咪管理、餐单管理、预约管理、领养管理、门店配置、时段配置 | 多角色权限、审计日志、商品/订单管理 |

> **说明**：预约押金采用**线下收款码转账 + 后台人工核验**方式（已与需求方确认，不接在线支付）。首页品牌静态内容（Hero/品牌故事/Slogan）写死在代码中，不做 CMS；后台仅管理业务数据。

## 2. 用户角色

| 角色 | 说明 | 权限 |
| --- | --- | --- |
| **前台访客** | 浏览官网的任何用户；无需注册登录 | 浏览首页/猫咪/餐单；提交预约（填手机号）；提交领养申请；查询预约状态 |
| **店主（管理员）** | 唯一后台账号，猫咖经营者本人 | 后台全部功能：内容管理、预约核验、领养审核、配置与统计 |

**角色设计说明**

- 前台**不开放注册登录**：预约/领养通过"姓名 + 手机号"即可提交，降低转化门槛（已确认）
- 后台仅 **1 个管理员账号**（用户名 + 密码登录），不做多角色（已确认）

## 4. 前台功能需求

### 4.1 首页

- **吸顶导航**：Logo「猫屿」+ 锚点/路由（猫咪/餐单/预约/领养）+「立即预约」按钮；首页内为**锚点跳转**至对应区块，进入独立子页（/cats、/menu、/reserve、/adopt）后为**路由跳转**
- **滚动交互**：滚动 200px 后导航切换为白色毛玻璃（backdrop-filter: blur）吸顶固定，预约按钮始终可见；当前区块/页面导航项显示 2px 暖橙下划线激活态；hover 提供焦点环反馈
- **移动端导航**：≤900px 断点收起导航项为**汉堡菜单**（展开 4 个导航项，触控目标 ≥44px，展开状态用 aria-expanded 管理）；页面底部固定「立即预约」按钮，预约转化路径不丢失
- **Hero**：Slogan「在猫的节奏里，慢下来」+ 全宽猫咪图 + 双 CTA（预约 / 认识猫咪）
- **品牌故事**：短句分段叙事（仿 MOCHA"想抚摸猫的时候/心情沉闷的时候/想拉近关系的时候"），文案在代码中维护
- **猫咪预览**：取前 6 只上线猫咪（按 sort_order），点击进详情；"查看全部 →"
- **餐单预览**：取 4-6 个代表菜品；"查看完整菜单 →"
- **安全须知**：消毒流程 / 互动规则 / 疫苗记录说明 —— 降低首次到访门槛，紧邻预约入口
- **门店信息**：从门店配置读取（地址/电话/营业时间/地图）；「立即预约」按钮
- **右侧悬浮横幅**：3 个迷你横幅（新猫报道 →/cats / 领养成功 →/adopt / 周边上新 → 后台可配置外链，暂指向公众号或电商店铺，无落点时可隐藏）
- **页脚**：Logo、导航、营业信息、社交（小红书/抖音/公众号 占位）、版权、隐私政策链接

### 4.2 猫咪模块

- **列表页**：卡片网格（照片/名字/性格标签/一句话故事）；「可领养」筛选开关；空状态治愈文案
- **详情页**：大图 + 全部档案字段 + 「预约来见它」（跳转预约页并预填意向）+ 领养入口（若可领养）

### 4.3 餐单模块

- 分类 Tab（咖啡/茶饮/甜品/猫零食）；卡片展示名称/价格/描述/图片；仅展示 `on_sale` 菜品
- 猫零食卡片标注"给猫咪的小零食"提示

### 4.4 预约模块（核心流程）

- **表单字段**：姓名\* / 手机号\* / 日期\* / 时段\* / 人数\* / 是否有 6 岁以下儿童 / 备注（含过敏史、想见的猫）
- **时段余量**：选择日期后实时显示各时段剩余名额（已确认 4 时段：11:00-13:00 / 13:00-15:00 / 15:00-17:00 / 17:00-19:00，每时段上限 6 组，后台可配）；周一自动置灰（店休，可配）
- **校验**：手机号正则（`1[3-9]\d{9}`）；日期不得为过去；满员时段禁用；单组 ≤6 人
- **防重复**：同一手机号同一天仅可提交 1 个预约（后端幂等校验）；前端按钮提交后置灰防重复点击
- **提交后**：自动确认并锁定名额（状态=待支付押金）→ 页面展示**店主微信收款码**（后台配置）与押金金额（默认 ¥20，可配）→ 顾客转账后填写**支付凭证**（转账单号，选填；转账人微信昵称/备注，必填）→ 提交后状态=押金待核验
- **预约状态查询**：输入手机号+预约单号可查状态（待支付/待核验/已确认/已取消）
- **自助取消**：状态查询页提供"取消预约"按钮（核验前可随时取消；已确认后取消需联系店主，押金按退款规则线下处理）
- **超时释放**：提交后 2 小时（可配）未填写支付凭证 → 自动取消并释放名额
- **通知机制**：核验通过 / 取消 / 退款结果由店主通过电话或短信**人工通知**顾客；前台状态查询页同步展示最新状态（双通道）

### 4.5 领养模块

- **页面内容**：情感入口文案（"把爱带回家"）→ 5 步领养流程 → 待领养猫咪卡片（adoptable=1）→ 申请表单 → 成功案例墙（"它们毕业回家啦"，数据来源：状态=已领养且填写了成功故事与照片的申请）
- **申请表字段**：姓名 / 手机 / 所在城市 / 意向猫咪（下拉）/ 居住情况（自有/整租/合租+室友同意）/ 养宠经验 / 家人是否同意 / 领养理由（开放题）/ 环境照片（选填，可上传 1-3 张）
- **提交后**：提示"申请已收到，我们会尽快联系您"，状态进入后台审核队列

### 4.6 隐私政策页

说明：收集手机号等个人信息仅用于预约联系与领养审核；不向第三方提供；支持删除申请记录（联系店主）。

## 5. 后台功能需求

### 5.1 管理员登录

- 用户名 + 密码登录；密码 bcrypt 加密存储；JWT 会话（有效期 7 天）；失败 5 次锁定 15 分钟（防爆破）
- 未登录访问后台任何接口返回 401，前端跳转登录页

### 5.2 仪表盘

- 今日预约数 / 待核验押金数 / 待审核领养数 / 在店猫咪数（实时统计）
- 近 7 日预约量趋势（简单柱状图）；最近 10 条预约列表
- **统计口径**：预约量默认按"预约日期"统计（即顾客计划到店日期），支持切换为按"提交时间"统计；仪表盘所有数字含今日实时更新

### 5.3 猫咪管理

| 操作 | 说明 |
| --- | --- |
| 列表 | 卡片/表格展示，含上下线状态与可领养标记 |
| 新建/编辑 | 字段：名字/性格标签/一句话故事/品种/年龄/性别/是否绝育/技能/照片(单张上传)/是否可领养/排序号 |
| 上下线 | 下线后前台不可见（不影响已提交的领养申请） |
| 删除 | 软删除（置 deleted 标记），防止误删 |

### 5.4 餐单管理

| 操作 | 说明 |
| --- | --- |
| 列表/新建/编辑/删除 | 名称/分类(咖啡/茶饮/甜品/猫零食)/价格(元)/描述/图片/上下架/排序 |

### 5.5 预约管理

- **列表**：按日期范围 / 状态 / 手机号搜索筛选
- **押金核验**：查看顾客填写的支付凭证 → 核对后点击"核验通过"（状态→已确认）/ "核验未通过"（状态→核验未通过，可填写原因，顾客需重新提交凭证）
- **状态操作**：标记已到店（→已完成）；取消（→已取消，释放名额，可备注退款情况）；标记爽约（→爽约）
- **时段余量总览**：日历视图显示各日各时段已约/容量
- 已确认数计入限流；取消/超时自动释放名额

### 5.6 领养管理

- **列表**：按状态筛选（待审核/待面谈/待家访/已领养/未通过）
- **审核流转**：店主手动推进状态：`待审核 → 待面谈 → 待家访 → 已领养` 或 `未通过`；每一步可填审核备注
- **回访记录**：已领养后可新增回访记录（日期 + 内容），历史回访列表展示
- **查看申请详情**：含环境照片与完整申请信息

### 5.7 门店设置

- 门店名称/地址/电话/营业时间/地图嵌入 iframe 代码/微信收款码图片（上传）/押金金额（元）
- 前台门店信息区与预约押金金额从此读取

### 5.8 时段设置

- 4 个时段默认容量 6（可改）；店休日配置（默认周一）；营业时段列表可增删

## 6. 核心业务流程

### 6.1 预约流程（含押金）

```
提交预约 → 待支付押金 → 填支付凭证 → 店主核验 → 到店/结束
（校验时段余量，自动占位）（展示收款码，2h内支付）（单号/昵称，待核验）（通过→已确认；不通过→退回待支付）（已到店/取消/爽约）
```

| 状态 | 触发条件 | 名额 |
| --- | --- | --- |
| 待支付押金 | 提交成功（自动确认占位） | 占用 |
| 押金待核验 | 顾客提交支付凭证 | 占用 |
| 已确认 | 店主核验押金通过 | 占用 |
| 核验未通过 | 店主核验不通过（填写原因） | 占用（限时重新提交凭证，超时自动取消） |
| 已取消 | 顾客自助取消 / 店主取消 / 超时未支付自动取消 | 释放 |
| 爽约 | 已确认但未到店 | — |
| 已完成 | 到店消费 | — |

> 限流规则：提交时校验 `该日期该时段 已确认+待支付+待核验+核验未通过 数 < 容量`（占用即计入，防止超卖）。

**押金退款规则（建议值，后台可配）**

| 场景 | 押金处理 |
| --- | --- |
| 核验通过前取消（待支付/待核验/核验未通过状态） | 全额退回（店主线下转账，后台记录退款备注） |
| 已确认后，到店日前 24h 之外取消 | 全额退回 |
| 已确认后，到店日前 24h 内取消 | 押金不退 |
| 爽约（已确认未到店） | 押金不退 |

### 6.2 领养流程

```
在线申请 → 待审核 → 待面谈 → 待家访 → 已领养
（填表+意向猫+环境照片）（店主查看资料）（门店见面互动）（线上/上门确认环境）（签协议，进入回访）
```

- 任一步可置为"未通过"（附备注）；"已领养"后可添加多条回访记录

## 9. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 首屏 LCP ≤ 2s；图片懒加载 + WebP；列表虚拟滚动（>500 条） |
| 图片处理 | 上传后自动压缩：长边限制 ≤1600px、体积压至 ≤300KB，并生成 WebP 缩略图（前台列表用）；原图不保留或保留于后台管理端（可配置） |
| 安全 | JWT 鉴权；密码 bcrypt；SQL 注入防护（ORM）；上传文件类型/大小校验 + 随机文件名；登录限流（5 次锁定 15 分钟）；押金凭证提交做手机号归属校验 |
| 并发一致性 | 预约提交的"名额校验 + 落库"必须在**同一数据库事务**内执行（SQLite 开启 WAL 模式，必要时对时段行加写锁），防止并发超卖；同一手机号同日唯一约束在应用层 + 数据库双保险 |
| 隐私合规 | 前台隐私政策页；手机号仅用于业务联系；领养环境照片仅店主可见 |
| 无障碍 | 色彩对比度满足 WCAG AA（正文 ≥4.5:1、大文本 ≥3:1）；主按钮色采用深橘 `#A94A26`（白字对比 5.68:1，**不使用** `#E8935F` 白字——2.39:1 不达标）；全站保留可见焦点环、图片 alt、语义化标签与键盘可达；动画尊重 `prefers-reduced-motion` |
| 兼容性 | Chrome / Edge / Safari 最新版；响应式（≥375px 移动端适配良好，Web 优先） |
| SEO | React SPA 默认 SEO 弱：为猫咪/领养等页面配置基础 meta（title/description 动态更新）；可选后续引入预渲染 |
| 可维护性 | 后端分层（router/service/model）；前端组件化 + 路由懒加载；代码仓库 Git 管理 |

## 10. 部署方案

> **现状**：服务器与域名尚未就绪（已确认）。以下为推荐部署方案，上线前需准备一台云服务器（2C2G 起步）与已备案域名（若使用国内服务器）。

- **单机部署（推荐）**：FastAPI（Uvicorn）同时提供 API 与托管 React 构建产物（`dist/`），SQLite 同机存储，图片存本地 `uploads/` 目录；Nginx 反向代理 + HTTPS（免费证书）
- **定时任务**：超时自动取消（2h 未支付）、逾期状态清理等定时逻辑用 **APScheduler 内嵌 FastAPI**（随 Uvicorn 启动，单进程运行即可）；或独立 cron 定时调用管理脚本（二选一，须保证不与 API 并发写冲突，共用同一 SQLite 时开启 WAL）
- **或 Docker Compose**：前端静态 + 后端 API 两个容器，一键启动
- **管理员初始化**：首次启动自动创建默认管理员（账号密码由环境变量 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 注入，或初始化脚本创建），上线后首次登录必须立即修改密码
- **数据备份**：SQLite 文件每日定时备份 + 上传目录备份
- **地图**：门店地图用高德/腾讯地图 iframe 嵌入（免 key，无需备案也可用）
