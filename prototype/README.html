技术说明

  • 纯静态实现：HTML + CSS + 原生 JS，无构建步骤、无外部 CDN 依赖，双击即可在浏览器打开
  • 共享样式：assets/app.css（设计令牌 + 组件），assets/demo-data.js（示例数据），assets/charts.js（自研 SVG 图表库）
  • 深色优先：默认深色主题，右上角太阳图标可切换浅色，选择存入 localStorage
  • 色彩空间：使用 oklch() 定义全部颜色，品牌色相 205（青蓝），刻意避开 bootstrap 蓝
  • 图表自绘：折线 / 多线 / 直方图 / 迷你走势线均为运行时生成的 SVG，随主题切换自动重绘
  • 响应式：≥900px 显示侧栏，<900px 折叠为抽屉；打印时自动隐藏原型工具条

呈现约定

  • 页面底部的 「原型说明」 区块（蓝色边框）列出该页与 PRD 需求编号的对应关系，不属于产品界面，交付时移除
  • 页头下方的 「演示状态」 药丸按钮用于切换空态 / 加载态 / 异常态，不属于产品界面
  • 红色的 「差异标注」 区块用于标识与参考网站（天池赛题页）不一致之处，已在下方第 6 节汇总
  • 页脚的免责声明是真实需求（任务书 §6.1），不是原型标注，需保留

关于本原型的覆盖口径
原型的目标是把交互与状态讲清楚，不是把 PRD 逐条点一遍。 因此：

③ P2 / P3 需求（截图导出、自动重训）明确标注为不在本期范围。

5. 示例数据说明

全部示例数据由 assets/demo-data.js 用确定性伪随机算法在浏览器内实时生成 ——同一份代码每次刷新得到完全相同的结果，因此截图与评审记录可复现。 数据结构严格对齐天池 167097 数据集。

5.1 数据集事实（联网核实）

项值来源
商品总数963 个天池数据集说明页
分仓数5 个（编码为字符串 1–5）同上
理论序列数963 × 5 ≈ 4,815 条推导
时间范围2014-10-10 ~ 2015-12-27（约 450 天）天池数据集说明页

赛题预测窗口固定未来 2 周（14 天）天池赛题页 ⚠️ 与本产品口径不同，见第 6 节

5.2 原型中的示例数据规模

完整 4,815 条序列对浏览器演示过重，因此抽样为 40 个商品 × 5 个仓、共 113 条有效序列（14,305 行）为演示集。 本页展示的每一次指标都来自该演示集的真实算法运行， 由 scripts/eval_report.py --export-series 产出后注入，并非手写数字。 按真实长尾分布，分级结果如下：

分级条数占比含义有效历史点数
L18171.7%历史充足，走 LSTM 模型推理≥ 90
L23228.3%单仓历史偏短，降级到商品级 + 按历史占比分摊< 90 但跨仓聚合充足
L300.0%跨仓聚合后仍不足 90 点，标记不可预测—

本演示集中三个 L2 商品（跨仓聚合足够但单仓偏短）由降级路径承接， 恰好验证了「L2 规则兜底」这条链路。真实天池数据集含更多极端长尾商品， L3 占比会明显上升 —— 三级降级机制正是为此设计。

5.3 指标数值得出的方式

页面上的 MAPE / MAE / RMSE / 达标序列占比来自 outputs/eval_series.json，即 eval_report.py 用 PRD §3.4.3 口径真实算出的结果，再由 sync_prototype_data.py 注入为 REAL_EVAL 常量。原型不再自己"算"一套，避免出现两套口径：

  • 加权 MAPE = Σ|yᵢ−ŷᵢ| / Σ|yᵢ| —— 主判定口径，门槛 ≤ 20%
  • 移动平均基线对同一批预测点、同一序列集合计算（PRD FR-MOD-06 🔒），确保「降低 15%」的结论可比
  • 达标序列占比只统计 L1 + L2（L3 不可预测，不参与评判）
  • L3 序列的预测值为 null，表格中显示「—」而不是用历史均值伪装成预测

本页展示的数值不是手写的示例数字，而是由 scripts/eval_report.py --horizon 14 --export-series 真实跑出后， 经 scripts/sync_prototype_data.py 注入 REAL_EVAL 常量。 当前这批数据的实际结果：加权 MAPE 14.26%（通过）、MAE 较基线降低 26.42%、RMSE 降低 27.52%、达标序列占比 83.95%。 全部满足或超过 PRD 设定的硬约束。

6. PRD 与参考网站的差异

参考网站为天池「菜鸟-需求预测与分仓规划」赛题页（dataset/167097）。 该赛题与本产品虽然共用同一份数据，但目标不同：赛题是「给定目标库存反推补货成本」， 本产品是「预测销量本身并在 60 秒内出结果」。 按需求，冲突时一律以 PRD 为准。下表列出全部差异。

维度天池赛题页本产品（PRD 为准）处置
预测步长 固定预测未来 2 周 7 / 14 / 30 天三档，默认 7 天 以 PRD 为准
预测目标 目标库存 target（反推补货成本） 销量预测值 forecast_sales 以 PRD 为准
评估指标 补货成本 A（补少）/ B（补多） 加权 MAPE ≤ 20% 且优于基线 ≥ 15% 以 PRD 为准
空间粒度 全国 + 分仓（含 all 汇总行） 仅「仓库 × 商品」，不预测全国汇总 以 PRD 为准
特征范围 30+ 行为特征（点击、加购、收藏等） 仅销量时序 + 时间 / 滞后 / 滚动统计特征 范围收窄，已标注
结果时效 赛题无实时性要求 端到端 ≤ 60 秒硬约束 以 PRD 为准
训练方式 赛题允许赛期内反复训练 纯预训练推理，不提供在线重训 以 PRD 为准
需要评审关注的一处能力收窄
特征范围这一项不是「口径不同」而是「能力收窄」： 天池赛题提供了 30+ 行为特征，本产品只使用销量时序。 这会让模型的上限低于赛题中的高分方案，但换来的是 「用户只需要上传一张销量表」这个可用性前提。 若后续希望提升精度，引入外部特征是明确的演进方向，但会增加用户的取数成本—— 这是一个产品取舍，需要在评审中确认。

8. 原型边界与待补充

8.1 本原型不做的事

  • 无真实后端：所有数据在浏览器内合成，不发起任何网络请求，不落库
  • 无真实模型：指标由公式模拟，不代表真实 LSTM 精度（真实精度须由训练脚本产出）
  • 无鉴权逻辑：登录 / 注册仅演示交互与校验提示，不产生会话
  • 不覆盖 P2/P3：图表截图导出（FR-VIS-10）、自动重训调度（FR-MOD-15）明确不演示
  • 不做多用户隔离验证：历史列表文案声明「仅展示你自己」，但无真实隔离逻辑

8.2 需要在评审中确认的问题

编号问题影响
Q-A 是否接受「仅用销量时序特征」带来的精度上限下降？ 影响模型目标是否可达 MAPE ≤ 20%
Q-B 30 天步长的结果是否允许展示？当前演示显示其 MAPE 超标且逼近 60 秒上限 影响是否需要禁用 30 天档位
Q-C L3 序列（不可预测）是否需要提供「转人工」的后续动作入口？ 影响结果页是否需要新增出口
Q-D 结果保留 180 天是否合适？是否需支持用户手动延长？ 影响存储容量规划与隐私策略
Q-E 跨任务对比的「最多 4 个」限制是否符合实际使用习惯？ 影响对比页交互复杂度

8.3 建议的评审顺序

  1. 首页 → 确认产品定位与价值主张的表述
  2. 上传页 → 确认字段契约与校验顺序（这是与外部系统对接的唯一入口）
  3. 参数页 → 确认粒度只读、步长档位、无重训选项
  4. 结果页 → 重点：确认指标口径、覆盖率披露方式、L3 的呈现策略
  5. 对比页 → 确认是否需要本功能（P1，可裁剪）
